# Pro Wi-Fi 中继

U30 Pro、F50 Pro 的入口为“网络 → Wi-Fi 中继”。支持主动扫描、选择或手动输入
SSID、开放网络／OWE／WPA2／WPA3 连接、断开、重连已保存网络和忘记网络。
企业认证不在此简化页面支持范围，扫描结果不会把企业网络当普通 PSK 网络连接。

网页与 U30 Pro 信息屏共用标准 wireless STA 配置和 `mu300.wifi-native` 后端，
由 netifd/wpad 管理接口和 DHCP，不再启动独立 wpa_supplicant。
F50 Pro 交付同一网页和后台，不启用屏幕服务。
扫描只由用户点击触发；页面可见时每四秒读取状态，后台没有周期扫描服务。
扫描和应用操作以互斥异步任务运行，不在 rpcd 调用内等待扫描或连接。
密码通过私有 stdin/0600 临时文件传递，不放入命令行或状态接口；任务读取后立即删除请求文件。

只修改选中的 STA，不改 AP 的名称、密码、启用状态和用户信道配置。
支持多信道并发的无线电保留热点已设信道，由驱动协调 AP/STA；单信道设备沿用
原有跟随上游的流程。扫描和 netifd 重新应用可能短暂影响无线性能；
这不是透明二层桥接。上网出口遵循已有接口的路由优先级，新建 wwan 使用既有默认
DHCP、metric 40 和 WAN 防火墙区域，不擅自更改蜂窝路由或用户配置。
如需优先走 Wi-Fi，请在标准网络接口页面明确调整路由优先级。

离线回归与下方列出的 U30 Pro 实机结果分别记录；F50 Pro 及其他上游 AP 的
兼容性不能由这一台 U30 Pro 的结果推定。
完整镜像／普通更新／差分更新均从 tracked Pro overlay 交付网页、RPC、权限和后台；
用户 wireless/network/firewall 设置保留，不把旧的 private 配置作为第二份设置源。

## 2026-11-20：连接上游后热点信标未恢复

本机只读日志显示 STA 已完成关联，但 hostapd 随后连续报 `Failed to set beacon
parameters`；手动重新启用热点后 AP 和 STA 可同时工作。现场 AP 配置仍允许启用。
固定版本 hostapd 的 AP+STA 路径在扫描时调用 `stop()` 移除信标，连接完成后却对
已经停止发信标的 BSS 调用 CSA。修复让停止过的 BSS 走现有 `start()` 流程；运行中
的 BSS 保留原来的 CSA 行为。未改写 AP 开关、SSID、密码、保存的信道或路由优先级。

修复位于 tracked `openwrt/patch-hostapd-sae.py`，通过原构建器重编匹配的 wpad、
hostapd-common、wifi-scripts，登记到 `wifi_apks`。普通构建和快速 sources 刷新均
安装该组合，并记录实际文件摘要；旧 DFS/信道补丁经过原结果核对后重新组合。
完整镜像、普通更新和差分 OTA 均交付实际程序文件。C 回归覆盖停止后恢复、正常
CSA、多个 BSS、错误返回和补丁幂等；离线通过与实机验收分别记录。

屏幕开关同时改为发送明确的 `wifi-on` / `wifi-off`。之前屏幕根据看板状态
计算目标，控制脚本却根据 netifd 拓扑再次取反；重载期间两个状态来源可能不同，
于是“开启”变成“关闭”。新流程直接把目标交给既有热点 owner，保留旧 toggle
入口的兼容性；专项模拟覆盖先开中继、再开热点，以及后续正常关闭。

同轮实机日志还确认了 fullmac 接口复用错误：AP 暂停发信标时 `operstate` 为
down，但管理标志仍为 UP。`wifi-scripts` 的 `find_reusable_wdev()` 将其误判为空闲，
把 wlan0 重命名为 wlan1，随后 hostapd 对已不存在的 AP 设置信标失败。现在根据
sysfs 的十六进制 flags 检查 IFF_UP，仅复用管理状态已关闭的接口，不接管仍由
hostapd／wpa_supplicant 管理的 AP／STA。实际 ucode 回归覆盖暂停的 AP、尚未关联
的 STA、真正空闲接口、消失的接口及 softmac。

U30 Pro 本轮热部署确认：开启中继后 AP／STA 同时存在；关闭热点再通过屏幕使用的
明确开启命令恢复热点，两接口仍同时运行，STA 获得 DHCP 地址并能访问上游网关。
不需要重启整机；用户的热点名称、密码、地区、信道和路由优先级均保留。此项是
接口／关联／上游连通性验收，不代表全部终端或长期吞吐验证。

## 网页布局与交付

网页沿用 SIP 插件的紧凑排版、主题变量、卡片、状态徽标和表单尺寸，但独立交付
`wifi-relay.css`，不依赖用户安装 SIP 插件。状态卡位于顶部，桌面下方为扫描列表与
连接表单双栏，手机为单列；列表超高时滚动，页面不吸顶。中文、英文、土耳其文
共用布局。扫描仍只由点击触发，不因页面展示、状态刷新或样式变化自动扫描。

网页、独立 CSS、RPC 与后端从共享 Pro overlay 同时进入 U30 Pro／F50 Pro 镜像。
实际差分生成／应用回归覆盖首次引入和后续升级，保留用户无线、路由、防火墙及
屏幕设置。`wifi-userspace.json` 同时记录 common.uc，防止漏交付接口复用修复。

## 2026-11-20：并发信道、上游缺失与跨频段

本机 AIC8800 驱动源码及实际 nl80211 能力均声明一个组合内允许 AP＋STA、最多
三个信道。没有采用固定 149／36 互换，也不改用户国家码。新增能力判断同时核对
一个组合的角色、接口数量和信道数量；不能把两个互斥组合拼成并发能力。

确认并修复了两个通用脚本问题：

- STA 扫描／认证／掉线事件会停 AP，配置生成器还会写入 `start_disabled=1`。
  对支持 AP＋STA 多信道的设备，两条路径均保留 AP；创建 AP 时也不再借用 STA
  的信道或等待其连接。明确关闭热点仍由原 owner 删除 AP，不被中继自动打开。
- 客户端默认扫描频率被限制为热点频段。现在多信道 STA 在没有用户显式
  `scan_list` 时，使用驱动当前允许的各频段频率；继续排除 disabled 信道并保留
  radio 范围约束。显式扫描范围、单信道设备及 mesh／adhoc 的原行为保留。

U30 Pro 实机对照：修复前上游不存在时 AP carrier=0；修复后 carrier=1。
热点信道 44／上游信道 36 可并发；热点 2.4 GHz 信道 1／上游 5 GHz 信道 36
可并发，STA 获得地址并能访问上游网关。当前原有 TR 地区禁止 149，实际生成的
扫描表没有 5745 MHz；没有为了试验放宽地区设置。其他国家通过真实 ucode 的
允许／禁止频率夹具验证，未声称所有国家／固件均完成实机验收。

修复统一进入 Pro 的三件匹配 Wi-Fi APK、原镜像／普通更新／差分交付。
receipt 也记录 `wifi/supplicant.uc`，避免仅交付页面或漏掉客户端生成器。

## 2026-11-20：蜂窝 IPv4 默认路由绕过用户跃点

源码确认：`mu300cell` 在初次拨号和 bearer 地址变化时手工执行不带 metric 的
`ip -4 route replace default dev ...`。这会额外留下优先级 0 的默认路由。
没有找到把用户 `network.*.metric` 配置改写成 0 的代码；被覆盖的是实际路由
选择效果，LuCI 中保存的跃点可以仍然正确。

核对固定版本 netifd `cbb83a18` 的 `proto-shell.c`、`interface-ip.c`、
`interface.c` 后确认：`address-external` 仅使地址保持外部所有权，协议通过
`proto_add_ipv4_route` 报告的路由仍由 netifd 安装，并继承接口的 metric、
路由表和 defaultroute 策略。之前的脚本注释错误地把路由也视为只读状态。

修复删除初次拨号、地址更新和 teardown 中额外的 IPv4 默认路由写入／删除，
保留外部地址管理和既有路由报告。由 netifd 的同一个路由 owner 处理优先级
变化，不新增服务、轮询、UCI 改写或基带重启。此次确认并修复的是 IPv4
优先级冲突；原有 IPv6 RA 管理和上报机制保持不变。

`tests/test_cellular_route_metric.py` 在隔离容器内使用同版本 OpenWrt 的真实
netifd、ubus、内核 dummy 接口，运行实际协议 setup 和报告函数，AT／背景
modem monitor 为夹具。通过 Wi-Fi 优先、Wi-Fi 跃点修改、蜂窝跃点修改且不
重拨、地址更新后保持优先级、回退蜂窝、显式 metric 0、禁用默认路由、
指定路由表和接口关闭清理九项。
原先 ARM/QEMU 的 netifd 子进程通知阻塞，未计为通过；改用已有的同版本
原生 x86 测试镜像后通过，未改动 netifd 或放宽生产协议。
